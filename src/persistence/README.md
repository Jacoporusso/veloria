# Save persistence contract

`save-store.ts` exposes a current in-memory save at schema version 2. Existing schema v1 records remain readable: `loadSave`, `importSave`, and `migrateSave` validate v1 before applying the pure v1-to-v2 migration. Missing v1 coordinates become `(0, 0)` because coordinates were optional in the v1 JSON Schema. Migration preserves all game fields and adds `saveRevision: 1`.

Every accepted save is checked deeply before it is returned or persisted: party and move limits, species/level/HP ranges, non-negative money/items, unique flags and creature instance IDs across party/storage, required player fields, and supported schema version. Current v2 creature records may omit `status` for backward compatibility; when present, it is one of `burn`, `poison`, `paralysis`, `sleep`, or `freeze`. Sleep requires a positive integer `turnsRemaining`; freeze may omit it for an indefinite duration or provide a positive integer. Burn, poison, and paralysis must not carry a timer. Invalid or unknown-schema records are not treated as a new game. IndexedDB stores each save payload under its existing slot key and a versioned FNV-1a checksum in a companion `checksum:<slot>` key in the same object store. Reads verify a present checksum before schema validation and can still read earlier raw records without a checksum; a successful legacy read adds the checksum, while schema migration backs up the original and checksums both slots atomically. Saving updates main and previous backup plus their checksums in one IndexedDB transaction. Local storage keeps the existing v1 key for compatibility and uses a separate previous-record key.

`save-backup.ts` is a pure JSON codec with no browser or filesystem dependency. `exportSave(save, exportedAt)` emits a versioned envelope containing the migrated save and a deterministic FNV-1a checksum. The checksum detects accidental corruption; it is not encryption or an authenticity signature. `importSave(json)` verifies the envelope checksum before validation/migration and also accepts legacy raw schema v1 or v2 JSON. The caller is responsible for deciding when to persist an imported save. IndexedDB payload checksums use the same stable JSON encoding and algorithm.

Stable encoding omits optional object properties whose value is `undefined`, matching JSON backup export. This preserves the checksum across an export/import round trip and allows cleared statuses to be saved; required values still pass deep validation first. Healing removes the creature's status property entirely. Existing checksums of JSON-only records are unchanged, and room map IDs add no serialized fields or migration.

The MVP Pokédex view is derived from the supported species catalog and the save's party/storage records. It counts unique species and owned instances without adding serialized fields; the first-act Pokédex tracks owned creatures, not sightings. Adding discovery history later requires an explicit versioned save migration.

The IndexedDB database version is independent from the serialized save schema version: v2 changes only record contents, so it does not require an object-store upgrade. Future serialized changes must add a pure migration function to `save-migrations.ts` and increase `CURRENT_SAVE_SCHEMA_VERSION`; do not rewrite earlier migration functions.
